**Goal:** Publish `@oxyhq/pay` — a Stripe-ergonomics TypeScript SDK over the existing Gateway REST + socket contract — with a **server-side** entry (`@oxyhq/pay`: `oxypay.paymentIntents.create()`, `.retrieve/.list/.reject`, `paymentLinks.*`, `checkout.sessions.*`, `webhooks.constructEvent()`) and a **browser** entry (`@oxyhq/pay/checkout`: `OxyPayCheckout.mount('#el', { clientSecret })` embeddable pay button + the payer-side REST+socket client core that the hosted checkout page also consumes). Third-party merchants (WooCommerce, Mercaria) are the audience, so it depends only on **published** packages.

**Architecture / auth:** The server SDK is configured with a confidential `ApplicationCredential` `{ publicKey, secret }` (`type:'service'`) — the SAME credential Oxy Console already issues, NOT a new "Oxy Pay API key" (spec §5). The SDK mints a short-lived Oxy **service token** by presenting `publicKey`/`secret` to oxy-api's `POST /auth/service-token` (the exact mechanism `oxyClient.serviceAuth()` validates at the Gateway, `paymentIntents.ts:117`), caches it until near expiry, and sends it as `Authorization: Bearer <jwt>` to `api.pay.oxy.so`. The credential's `environment` (development/staging/production) rides in the minted JWT (F2.0 upstream), so the Gateway resolves the correct test/live `Merchant` automatically — the SDK never sends a `livemode` flag. `Idempotency-Key` is a real header (`paymentIntents.ts:122`); the SDK exposes it via `.create(params, { idempotencyKey })`. The browser entry needs NO service token — it holds only a public `client_secret` (read snapshot + socket subscribe + `submit_tx`), the exact payer capability the wallet already uses.

**Tech Stack:** TypeScript, zero-runtime-dep server core over `fetch` (Node 18+ global fetch); `socket.io-client` for the browser entry (matching the Gateway's Socket.io transport, mirrors the wallet's `gateway-socket.ts`); dual CJS+ESM+types build (tsdown/tsup — match `@oxyhq/contracts`, see Task 1). `bun test`.

## Global Constraints

- **Third-party-consumable = published deps only.** `@oxyhq/pay` and its transitive `@oxypay/shared-types` must resolve from npm for an external `bun add @oxyhq/pay` — NO `workspace:*` deps may survive into the published tarball (verify by packing + inspecting, per AGENTS.md). Publish `@oxypay/shared-types` FIRST (Task 1), verify with a clean external install + `import()`, THEN publish `@oxyhq/pay`.
- **One signing algorithm, one copy.** `signWebhook`/`verifyWebhook` (currently `backend/src/services/webhookSigner.ts`, zero-dep over `node:crypto`) MOVE to `@oxypay/shared-types` so the Gateway signs and the SDK's `webhooks.constructEvent` verifies with the SAME code — the algorithm can never drift. The backend imports them from shared-types afterward (clean cut; delete the old file, update `webhookDispatcher.ts`'s import).
- **Non-custody invariant.** The SDK server core speaks only `amount`/`network`/`metadata`; the browser core holds only a public `client_secret` + a read-only socket. NO private key, seed, or signing path ever enters this package. `security-reviewer` MUST review the SDK diff before it is used against `livemode:true` (spec §2 — a public npm surface not covered by the F1 audit).
- **Mirror the wire contract, don't redefine it.** Every request/response type comes from `@oxypay/shared-types` (`PaymentIntent`, `CreatePaymentIntentParams`, `PaymentLink`, `CheckoutSession`, `WebhookEvent`, …). The SDK adds only ergonomics (resource namespaces, idempotency option, typed errors), never a second copy of a DTO.
- **Error mapping.** The Gateway returns `{ error: { type, message } }` (`http.ts` `sendError`). The SDK maps non-2xx into a typed `OxyPayError` hierarchy (`OxyPayAuthenticationError`, `OxyPayInvalidRequestError`, `OxyPayPermissionError`, `OxyPayApiError`) keyed off `error.type` + HTTP status — never throw a bare `Error` or leak a raw `Response`.
- **Clean code:** no `as any`, `@ts-ignore`, `!`, `var`, `console.log`, silent `catch {}`, TODO/HACK, barrel/re-export shims. Direct imports from owners.
- **Package manager:** `bun` only; commit `bun.lock` with each `package.json` change in the SAME commit. Use the `publish` skill for the npm release + downstream bump flow.

- [ ] **Step 3:** Unit tests (stub fetch + a mock socket). Commit.

> **HARD BACKEND DEPENDENCY — anonymous payer realtime.** The Gateway socket authenticates the *connection* with an Oxy identity token (`realtime/socket.ts:46` `io.use(oxyClient.authSocket())`; handshake `auth.token`). A third-party embed buyer and the hosted checkout page (checkout+links plan) are **anonymous** — no Oxy session — so their handshake is rejected and `subscribe` never fires. Room-join is ALREADY authorized per-intent by `client_secret` + `verifySecret` (`socket.ts:59-66`), so the connection-level identity gate is redundant for the payer path. **This task includes the backend change:** allow an anonymous (token-less) socket connection for the payer path — either make `authSocket()` optional on this server (an "optional identity" connection that still requires a valid `client_secret` on every room join) or add a dedicated payer namespace (e.g. `/checkout`) with only the `subscribe` handler and no identity requirement. Whichever is chosen, EVERY room join must still `verifySecret` — do not weaken that. This is an **owner-facing security decision** (surface it): weaken connection auth vs separate namespace vs REST-poll-only. Until it lands, `subscribe` falls back to short-interval REST polling of `getPaymentIntent` and the caller is told realtime is degraded. `security-reviewer` reviews this change.
